# ADR 0001 — 召回由检索维度决定，不由排序决定

- 状态：已采纳
- 日期：2026-11-13

## 背景

项目最初假设瓶颈是“排序不准”：候选池里已经有相关文献，只是排得靠后。
在真实数据上验证时，这个假设被推翻了。

## 证据

用同一份金集（7 篇被领域研究者逐篇读全文并判定为真耦合的文献）测三套口径：

| 口径 | 池子 | 金集覆盖 |
|---|---|---|
| 仅 COF | ~1000 | 2 / 7 |
| 六类材料体系并集 | ~3000 | 5 / 7 |
| 六体系 + 三条修正 | — | 7 / 7 |

在 COF 单一口径内，增加耦合词、增加底物词、缩小到 201 篇子集，
覆盖率**始终是 2/7**。原因是缺失的 5 篇里有 4 篇不属于 COF 体系
（CMP、PHI、碳氮、CdS），摘要里不出现任何 COF 字样。

## 决定

1. 检索层必须**多维度并行**；单家族检索只能是显式选项，不能是默认。
2. 不做“排序提升召回”的承诺；排序只影响人工阅读的先后。
3. 金集与候选池分离：金集测召回，负例测误召回，两者不混算。

## 后果

- `packages/core/src/profiles/families.ts` 把“材料族”作为一等概念。
- 基准分成三段，而不是只报一个总分。
- 任何“只改排序”的优化，都必须先证明它不动召回分母。

## 2026-11-19 更正：5/7 那一步其实是词形问题，不是维度问题

补上复数变体后重测（cap 1000，全部查询成功的一次）：

```
A. COF only                       814       2/7
B. six material families          2826      7/7
C. six families + 3 fixes         2837      7/7
```

**六族并集自己就到 7/7。** 以前需要两条修正（`spaced-formula`、`no-product-word`）才能捞到的两篇，
现在分别由 `Bi` 轴和 `CN` 轴直接命中——因为查询词补了 `bismuth oxysulfides` 和 `carbon nitrides`。

### 这对原判断的影响

原判断「召回率由检索维度决定，排序补不回来」**仍然成立**，而且更强了：
- 单轴口径内，加耦合词、收窄子集、换排序，2/7 一动不动；
- 六条轴并集，7/7，且**每篇各由一条轴独立召回**（`--probe` 可逐条核）。

但「三条修正把 5/7 补到 7/7」这个叙事是错的：那两条修正当时补的是**词形**（单数匹配不到复数），
不是**维度**。修正项仍然多捞 11 篇唯一文献，但不再是召回瓶颈。

### 池子变小了

814 / 2826 / 2837，比之前的 922 / 2877 / 2896 略小——因为同一轮加了记录类型过滤
（peer-review、dataset、paratext 不是文献记录）。**这是修正，不是退化。**
