# v0.2 设计 — 判据库（Criteria Packs）

> 状态：设计稿，未实现。
> 目标：把"导师随口说的三句话"变成可 diff、可评审、可执行、可版本化的文件。

## 1. 为什么是文件，不是数据库

判据是**这家实验室的判断**，它的价值在于可被质疑、可被 diff、可被 fork。
放进数据库，评审看不见、变更说不清、fork 走不动。放进仓库：

- 每次口径调整都是一次 commit，带作者、时间、理由；
- 用户可以直接 `git diff` 看"标准怎么变的"；
- 别的课题组可以 fork 一份改自己的判据，而不是提 issue 求人加参数。

产物只有一个目录：

```
criteria/<pack-name>/
├── pack.yml        # 元信息 + 判据列表
├── precedents.yml  # 判例（带 DOI 的真实裁决）
└── README.md       # 这个课题组为什么这么判
```

## 2. 判据的结构

```yaml
- id: C-COUPLE-01
  version: 1
  text: "耦合不要求同一个体系：串联、分步、前后两个体系都算"
  severity: hard          # hard = 触发即改判；soft = 只降级
  section: ["3.2(1)", "3.2(3)"]
  check:                  # 可机检部分；没有可机检部分就留空
    kind: keyword
    any: ["tandem", "sequential", "step-wise", "in a separate step"]
  examples:
    positive: ["10.1038/s41467-025-62937-x"]
    negative: ["10.1016/j.mser.2025.101117"]
  rationale: "写清楚为什么这条成立，以及它在什么情况下不成立"
```

两条强制约束，检查不过就不许合并：

1. **每条判据必须至少一个正例、一个反例。** 没有例子的判据是口号。
2. **`check` 为空的判据必须标 `manual: true`**，并且判定结果里只能出现在"待人工"列表。

## 3. 判例的结构

判例是"这条判据在某个具体文献上怎么用的"，它比判据更有说服力，因为可追溯。

```yaml
- case: P-0007
  doi: 10.1021/jacs.6c00731
  verdict: 2               # 2 相关 / 1 部分 / 0 不相关
  criteria: [C-COUPLE-02, C-TRAP-01]
  rationale: >
    摘要头条 17768.4 μmol g⁻¹ h⁻¹ 来自 10% 苯甲醇牺牲剂组；
    耦合组数据在正文，为 24 mM。两套实验溶剂不同，故判为"同一材料两种功能"而非耦合。
  decided_by: 领域研究者
  decided_at: 2026-11-10
```

## 4. 判定输出契约

v0.2 不输出"相关 / 不相关"，只输出建议 + 依据 + 待人工项：

```json
{
  "doi": "10.1021/jacs.6c00731",
  "suggestion": "partial",
  "cited": ["C-COUPLE-02", "C-TRAP-01", "P-0007"],
  "evidence_hints": [
    {"criterion": "C-FIG-01", "text": "去图 3 看是否同图给出两种产物随时间变化"},
    {"criterion": "C-TEXT-02", "text": "正文搜 simultaneous；摘要出现 0 次"}
  ],
  "caveats": ["头条产率可能来自牺牲剂组"],
  "needs_human": true,
  "criteria_version": "cof-h2o2@1.2.0"
}
```

规则：`cited` 为空 → 输出作废；`needs_human` 永远为 `true`。

## 5. 版本与回归

- 判据包用 semver：新增判据 = minor，改判定逻辑 = major，改措辞 = patch。
- 每次判定都记录 `criteria_version`。
- 判据一变，**必须重跑基准**；覆盖率或召回变化写进 PR。
- 基准里固定"判据版本 + 端口日期"，否则数字无法比较。

## 6. LLM 的位置

v0.2 的 LLM 只做两件事，且都在人之后：

1. **起草判据**：把一段讨论记录抽成 `pack.yml` 草稿 —— 输出必须经人签收才进仓库；
2. **补充证据提示**：读摘要，指出"这里可能出现牺牲剂组" —— 属于 `caveats`，不影响 `suggestion`。

绝不让 LLM 直接写 `verdict`。`verdict` 只有两种来源：人工，或已经人工签收过的判例。
