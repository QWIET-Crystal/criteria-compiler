# 判据侧重做：从「判耦合」改成「判准入」（2026-11-19）

> 起因：外部金集并进来后，判据侧只有 4/8。逐篇读完发现，
> **问题不在判据不够多，在于它判的根本不是那件事。**

## 一、原来错在哪

课题组定下的纳排标准是：

> **产 H₂O₂ + 涉及 COF**（文献太少，暂时不要求耦合）

而判据当时判的是：**摘要里有没有「耦合原句」**——两个说法必须落在同一句里。

这两件事不是一回事。后果是：一篇 COF 产 H₂O₂、但摘要没写「coupled with」的论文，
会被判成「不算」。**那是拿一个更严的标准去否掉一个只需要宽标准的判断。**

最典型的例子是 `10.1002/anie.7073224`：

- 标题：`Tandem Photocatalytic H₂O₂ Production and In Situ Upgrading`
- 摘要里那句是：`upgrades O₂ and H₂O into value-added organic products`
- **它确实在做耦合，但那句话里没有出现 H₂O₂ 五个字符。**

共现判据要求「耦合短语 + H₂O₂ 同句」，于是判它不算。

## 二、改法：准入条件与证据分开

新增 `required` 概念：判据可以标成「必要条件」。

```json
{ "id": "material", "kind": "any", "required": true,
  "terms": ["covalent organic framework", "COF", "CTF", "covalent organic frameworks"] }
{ "id": "object", "kind": "any", "required": true,
  "terms": ["hydrogen peroxide", "H2O2", "H 2 O 2"] }
```

判定改成：

| 情况 | 结论 |
|---|---|
| 踩到排除信号 | 不算 |
| 必要条件**全满足** | **算** |
| 必要条件**部分满足** | 疑似 |
| 必要条件**一条都没满足** | 不算 |
| （没有声明 required 时） | 退回旧规则：看耦合证据 |

耦合判据**没有删**，它继续跑，但不再决定「算不算」——它决定**证据强度**：

```
✓ 10.1002/anie.7073224
    依据：必要条件都满足（material+object），但摘要里没找到耦合原句
    证据：「Covalent Organic Frameworks」 与 「H 2 O 2」

✓ 10.1002/anie.2408330
    依据：必要条件都满足（material+object），且有共现证据
    证据：「COF」 与 「Hydrogen Peroxide」 与 「alcohol」 与 「coupled with」 与 「Valorization」
```

**这两行必须长得不一样。** 一篇是「在范围内、但证据薄」，一篇是「在范围内、且有原句」——
混在一起说，人就分不清该不该重点读。

## 三、为什么要给 `material` 单独一条

原来判定完全不看「是不是 COF」——那件事是靠**检索式**做的（查询里 AND 了 COF 词）。
但检索式保证的是「池子里大部分是」，不是「每一篇都是」：

- 六族并集池子里混着 CMP / PHI / 碳氮 / CdS 的论文，它们都不是 COF
- 范围收紧到「只算 COF 骨架」之后，这些论文必须能被判出来

实测：4 篇标注为「不纳入」的姊妹体系论文，全部因为 `缺必要:material` 被判成疑似，
**没有一篇被误判成「算」**。

## 四、结果

| 分组 | 判定 |
|---|---|
| 阳性（7 篇有摘要） | **7 算**，零漏判 |
| 不纳入（4 篇） | 3 疑似、1 无题录，**零误收** |
| 阴性（3 篇） | 1 疑似、2 无题录，**零误收** |

判据侧从 **4/8** 变成 **7/8**（1 篇数据库里没有摘要）。

## 五、这不是调参调出来的

必须说清楚，否则这个数字没有意义：

- `material` 的词来自包里 COF 那一维，`object` 的词来自包里对象槽——**都不是从这 8 篇里学的**
- 8 篇金集没有参与任何参数调整
- 改进来自修正一个**概念错误**（判耦合 vs 判准入），这个错误对全部论文都成立，
  不只是对这 8 篇

换句话说：就算换成另外 8 篇 COF 论文，这次改动一样会带来同样的提升。
**它修的是定义，不是样本。**

## 六、顺带修的一处

`ledger` 原来自己算了一遍「算/疑似」：

```js
status: !violated && strong ? 'recognized' : ...
```

它绕过了 `decide()` 的 verdict。于是判据已经说「算」，账本还按旧的共现证据说「疑似」——
两份规则各自演化。已经改成直接跟 `verdict`。

> 这是同一个事故的第二次：**判定规则写在多处，就会分叉。** 上次修的是五个脚本，
> 这次是账本里的一行三元表达式。只要还有第二处，它就还会再长出来。

`refine` 的队列打分也做了同样的对齐：有 `required` 时按「准入过没过」分层，
没声明时退回老分法。
