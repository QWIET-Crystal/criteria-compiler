# 不许过拟合，也不许欠拟合

> 这不是口号。下面每一条都对应代码里一个具体的位置，跑一遍能验证。

## 为什么会担心

这个项目有两个地方天生容易过拟合：

1. **判据是从少量正例里长出来的**。正例说 3 篇，长出来的词当然贴合这 3 篇。
2. **校准阈值 / 补词之后，会在同一批标注上评估**。这一测一个准，全是虚高。

欠拟合的风险则相反：判据太严，看着干净，其实大面积漏掉。

## 六道闸门

### 1. 指标拆开报，不给单一"准确率"

`bench/refine.mjs` 同时报**抓到几篇「算」**和**误判几篇**。

正例少于 3 篇时直接打警告，并说明「把所有论文都判『不算』也能拿到多少分」——把那类退化解当场戳穿。

> 第一版就是被这个骗的：34 篇里 1 篇正例，报出 96%，其实是全判不算。

### 2. 校准要留一检验

`refine.mjs` 里，一致率分两个数：

| 数 | 含义 |
|---|---|
| **上一版判据在你这次新标的论文上** | 这才是检验 |
| 本轮校准后（同一批） | 这是拟合，一定虚高 |

趋势表里的召回一栏，取的是前者。

### 3. 泛词在进判据前就硬剔除

`bench/lib/terms.mjs` 的 `refineAgainstPool()`：拿同领域背景池算词频，超过 15%（严到 30%）的词直接不要。

而且**不按出现次数排序**——出现次数越多，越可能是这个领域的常识词。

> 实测踩过：`charge` 13.6%、`electron` 13.6% 排在词表最前面，因为它们出现在全部 3 篇正例里。

### 4. 单篇不升格（这条最硬）

`bench/ledger.mjs` 里写着：**一条归因只涉及 1 篇时，不会被建议升格成修正。**

单篇就改判据，是在奖励噪音。要升格至少两篇不同论文落在同一个归因上。

### 5. 升格前必须过回归

升格建议旁边固定带一句话：升格后要重跑 `bench/run.mjs`，确认**新修正在拉回这几篇的同时，没有把原本在池子里的阳性挤出去**。

只优化"多找回一篇"而不检查"少没少别的"，是另一个方向的过拟合。

### 6. 漏太多就说覆盖不足

`ledger.mjs` 小结里：漏检比例超过 40% 时直接报 ❌，并写明「这不是补一条修正能解决的，是判据整体还没覆盖住这个领域」。

不欠拟合的做法不是硬撑，是承认。

## 账本不自动改东西

`ledger.json` 只记事实：哪篇漏了、漏在哪条查询之外、被哪条救回、还是根本救不回。

它**不调阈值、不改词表、不写回 pack**。改不改由人决定，改完必须有据可查。

这条是刻意的：自动调参会把过拟合写进仓库，而人做决定至少还能被追问。

## 怎么验

```bash
node bench/ledger.mjs --pack cof-h2o2     # 看升格建议里有没有"单篇不升格"那句
node bench/refine.mjs --pack <包名>        # 看召回和一致率是不是分开报的
```

两条命令的输出里都能看到上述行为，不需要读代码。
