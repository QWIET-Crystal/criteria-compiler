# 区分词质量审计（2026-11-19）

> 起因：判据侧的「疑似」覆盖到 88/100 甚至 269/270——`core-any` 几乎不筛东西。
> 这轮想把「哪些词其实不区分任何东西」量出来。

## 方法

用一份**跟候选词无关**的背景：本地 120 篇带摘要的同领域池子，对比 6 篇有摘要的金集阳性。

```
lift = 这个词在阳性里的覆盖率 ÷ 它在背景池里的覆盖率
```

lift ≈ 1 表示这个词在阳性和背景里一样常见——**它什么都没区分出来**。

## 结果

| 词 | 阳性命中 | 池子占比 | lift |
|---|---|---|---|
| intramolecular | 33% | 7% | **5.00** |
| asymmetric | 33% | 7% | **5.00** |
| alcohol | 50% | 18% | 2.86 |
| donor | 50% | 23% | 2.22 |
| acceptor | 33% | 20% | 1.67 |
| sacrificial | 33% | 28% | 1.21 |
| production rate | 33% | 34% | 0.98 |
| photosynthesis | 33% | 36% | **0.93** |

**`photosynthesis` 的 lift 是 0.93**——它在池子里比在阳性里还常见。
把它当「区分词」放进判据，等于让判据对整个同领域都成立。

## 为什么没有自动剔除

我先把它做成了硬过滤（`lift < 1.5` 就丢），跑完发现**它一次都没触发**。

原因：工具自己的背景池是「命中任一候选词」的论文，分母有偏。
在这个池子里 `photosynthesis` 的 df 只有 2.1%，lift 反倒算成 **31.9**。

同一个词，中性样本里 lift 0.93，工具池子里 31.9。**拿有偏的分母做自动剔除，
会把好词坏词一起切掉，而且没人看得出来。**

所以回退了。这件事本身记在这里，因为它是这个项目反复出现的同一类错误的又一例：
**一个从不触发的过滤器，比没有更糟。**

## 建议（需要人来定）

`core-any` 现在 8 个词里，真正在区分的是前 4 个。
后 3 个（`sacrificial`、`production rate`、`photosynthesis`）lift ≤ 1.21，
**建议删掉或替换**——但这个判断得由了解这个领域的人做，不是脚本该替的。

## 真正的修法（未做）

背景池应该按**对象词**取（例如只搜 `hydrogen peroxide`），而不是按候选词取。
那样 df 才代表「这个领域的常识程度」，lift 才有意义。

代价：多一次池子请求，且会改变队列构成，需要重测——留给下一轮。

# 处置：三个词，三种处理（2026-11-19 下午）

审计之后按「删 / 拼接 / 转判据」三条路做了实验，**两次做错、两次撤回**，最后落在三个不同的层上。

## 最终处置

| 词 | 处置 | 为什么 |
|---|---|---|
| `photosynthesis` | 从判定词表剔除；**仍留在检索词表与共现配对里** | 单独出现不区分（lift 0.93），但和 `aerobic` 撞在同一句里能认出 jacs.6c00731 |
| `production rate` | 同上 | 通用指标说法，lift 0.98 |
| `sacrificial` | 做成 `note` 判据：**只给证据，不参与判定** | 见下面第二次失败 |

## 第一次做错：lift 换不来精度（详见上文）

硬过滤一次没触发，因为分母有偏。回退成「只算不筛」。

## 第二次做错：把「用了牺牲剂」写成排除项

`polarity` 一开始是 `absent` 判据：出现 `sacrificial` 且非否定 → 不算。

跑完金集直接从 **2 篇认得出掉到 1 篇**。查下去，被误杀的是
`10.1021/jacs.6c00731`——它的摘要明写：

> using benzyl alcohol as a sacrificial agent

**但它同时产出了苯甲醛，按课题组标准仍然算耦合**（真实记录第 49–53 行：
「因为产生的苯甲醛是有价值的……只提升催化性能没有其他产出，才算牺牲剂」）。

也就是说：**用没用牺牲剂，本身不是判「不算」的依据。**
依据是「有没有同时产出有价值的东西」——那不是词频能表达的东西。

改成 `note`：它把「以肯定形式 / 否定形式出现了几处」摆出来，**不改变判定**。
判据说 算，同时告诉你「这篇用了牺牲剂，你看一眼」。

## 第三次做错：两个清单又合并了

为了让共现对用全量词表，我把 `termList` 一起改了——
结果 `core-any` 也用回全量，刚删掉的噪音词原路返回。

修法：明确拆成三份。

| 清单 | 用途 | 宽窄 |
|---|---|---|
| `searchTerms` | 拼查询（`refine` 重拉用） | **宽**，含噪音词 |
| `pairTerms` | 共现配对 | 中，df ≤ 5% 的稀有词 |
| `core-any`（`mustHave`） | 判定 | **窄**，剔除噪音与极性词 |

## 结果

| | 改之前 | 改之后 |
|---|---|---|
| 金集（算/疑似/漏） | 2 / 3 / **1** | 2 / 4 / **0** |
| 池子 120 篇「够到」 | 97 | **86** |

**一个漏检被救回来，同时池子少 11 篇噪音。**

## 一句话

「删掉」和「必须与其他词拼接」不是同一个层面的两个选项：

- **删** = 判定层的事
- **拼接** = 共现判据，本来就是另一个判据形式
- 而**检索层**要的是相反的——词越多越宽越好

把它们混成一个「词表」，就会反复出现上面那三次错误。
