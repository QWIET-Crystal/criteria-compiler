# 准绳 · 设计树

> **根目标**：把一个人脑子里的边界判断，变成一套别人能跑、能查、能接着改的东西。
>
> 状态：2026-11-15 ｜ ✅ 已实现　⚠️ 缺口　⊘ 主动不做

---

## 1. 表示层 —— 标准长什么样

### A1 标准是配置，不是代码 ✅
- **选择**：一个领域所需的全部内容放 `packs/<domain>/pack.json`；引擎里不出现任何领域词。
- **理由**：换领域不改代码。这条不是口号，`bench/validate-pack.mjs` 拿 pack 里 49 个词逐个搜 `packages/*/src`，出现一个就 fail。
- **代价**：配置要人写。但学生版把「写」降成「改」：用户只给一句需求 + 几篇正反例，系统起草，人只删改。**专家不消失，从作者变成审稿人。**

### A1′ 隐性假设：对象与方法要能在论文自述里出现 ⚠️ **已验证的边界**
- **假设内容**：pack 的槽位词，必须在目标论文自己的标题/摘要里出现过，检索才可能命中。
- **在 COF 上成立**：`h2o2` 槽单独 295,893 篇，单槽无交叉问题。
- **在「视觉 × ESG/金融」上不成立**（2026-11-16 实测，`bench/axis-yield.mjs`）：

  | 量 | 值 |
  |---|---|
  | `application` 槽单独 | 432,789 |
  | `method` 槽单独 | 747,317 |
  | 两槽 AND | **350**（交叉率 0.1%） |
  | 六条轴产出 | 18 / 13 / 10 / 0 / 33 / 33，并集 100 |

- **不是词表写错，也不是 AND 失效**。逐项排除过：
  - `CHARTS` 轴三个词各自 214 / 111 / 58 篇，OR 起来 356 篇 —— 词是对的；
  - `annual report`(197,557) AND `table extraction`(311) = 4；`ESG`(74,599) AND `OCR`(16,014) = 4 —— AND 真的在收窄。
- **成因**：这个领域**论文写任务名，不写学科名**。写"表格抽取"的论文不会同时写"年度报告"。
- **去掉 method 槽的对照**：并集 1,454 篇、六轴 15,932 / 2,111 / 1,067 / 0 / 2,817 / 2,175 —— 池子活了，但精度塌（`DISCLOSURE` 那 15,932 篇绝大多数与视觉无关）。
- **结论**：留着太严、去掉太松，**不是词表能修的，是槽位设计的判断**。这类判断只有领域专家能做，因此它是"专家版产品"不可替代的入口，而不是一个可以自动化掉的参数。

### A2 标准拆成四件，每件有唯一归宿 ✅
| 自然语言里的东西 | 落到哪 | 例 |
|---|---|---|
| 必须同时满足 | `slots`（全部 AND） | 产物槽 = hydrogen peroxide |
| 可枚举的旁支 | `dimensions`（各自查询后并集） | COF / CMP / PHI / C3N4 / CdS / 铋系 |
| "上次漏了的那篇" | `extraQueries`（必须写 `why`） | 化学式空格变体 |
| "看起来像但不算" | `checks` / 判据规则 | 牺牲剂体系 |

- **代价**：⚠️ **没有 `exclude` 一等字段**。"不要加了牺牲剂的"这类否定约束只能塞进 `extraQueries` 手写 NOT，或落到判定层事后标记。

### A3 判据写成规则，不写成分数 ✅
- **选择**：`check_rN(doc) -> list[Hint]`，命中就是命中，不命中就是不命中。
- **理由**：不依赖金集。分数要阈值，阈值要人工标注调——那就滑回"没有标注就不能用"。
- **代价**：规则要人写；措辞完全不同的论文抓不到。

### A4 判据必须能处理否定语境 ✅
- **选择**：`has_negation(text, pos, window=40)`；`without any sacrificial agent` 不判成牺牲剂体系，改报 R14。
- **理由**：这是"概念边界"最容易被文本匹配骗过去的地方，也是最像人类判断的一处。

### A5 提示文案有硬上限 ✅
- **选择**：`hint.text` ≤ 40 字（测试强制）。
- **理由**：提示必须短到能一眼扫完。写不下就得说人话。

## 2. 检索层 —— 怎么保证"进得来"

### B1 多轴并行，不是一个大 OR ✅
- **选择**：每个 dimension 单独查询再合并。合并成一个 OR 就失去了"哪条轴贡献了什么"。
- **证据**：同一题目，单轴 2/7 → 六族并集 5/7 → 加修正 7/7。而在单轴口径内，加词、收窄子集、换排序，数字**一动不动**。
- **结论**：召回率由检索维度决定，排序补不回来。（ADR-0001）

### B2 修正项必须绑定一篇具体漏检文献 ✅
- **选择**：`extraQueries[].why` 写明它救回的是哪一篇，否则校验不通过。
- **意义**：这是"漏检账本"的种子——别人记录"排除了什么"，我们记录"漏掉了什么"。

### B3 表层归一化 ✅
- 化学式空格（`H 2 O 2` → `H2O2`）、DOI 规范化、单位不混比。

### B4 单一数据源 + 兜底，不堆库 ✅
- **选择**：核心只接 OpenAlex；Crossref 作为第二源在 bench 层。
- **理由**：7 篇阳性金集**全部**来自 OpenAlex，说明漏检不是库的问题；多堆几个收录高度重叠的源，收益接近零。
- **代价**：⚠️ 看不见中文文献、专利、试验注册；看不见全文，只有题录 + 摘要。

### B5 靠"预想得到的扩展"，而不是语义召回 ✅ / 残差不可测
- **选择**：不用 embedding 做召回；用同义词 + 兄弟族扩展 + 换轴。
- **已覆盖的证据**：2/7 → 5/7 那三篇，全靠把材料轴从 COF 扩到 CMP / PHI / CdS 救回来的；再加两条修正到 7/7。**对这 7 篇而言，扩展已经够了。**
- **救不回来的那一类**：一篇论文如果**完全不出现**该领域的任何词，同义词再多也没用。
  - 实例：`10.1038/s41467-019-08454-0`，摘要从不出现 H₂O₂（它是瞬态中间体）。救它的是**换轴**（改用底物 + 目标产物去搜），不是同义词。
- **残差有多大，不可测**：金集是人凑出来的，里面本来就只会有"已经知道的那批"。缺的那批没有分母，所以只能说"不知道丢了多少"。
- **对策按成本排序**（都不需要语义模型）：
  1. 正向雪球（谁引用了种子）——用引文图绕过词汇，最便宜，**目前未做**
  2. 术语挖掘：从已召回摘要里找高频但词表外的新词，提示加轴（可解释）
  3. 借一篇权威综述的参考文献当召回下界
  4. 语义近邻——最后才考虑，因为它不可复核

### B6 种子偏差：从"已筛清单"出发会继承它的筛选偏置 ⚠️ **已发生在我们自己身上**
- **问题**：如果候选池不是从原始检索长出来的，而是从一份**已经按某个标准筛过的清单**出发再补，那么清单本身的筛选偏置会整段继承下来，而且看不出来。
- **我们踩过**：`data/201-with-abstracts.csv` 是从"已经判过是耦合"的清单出发、只往后补 2024–2026 得来的。实测年分布：

  | 年份 | 篇数 |
  |---|---|
  | ≤2020 | 2 |
  | 2021–2023 | 19 |
  | 2024–2026 | **180** |

  2021 年以前只有 2 篇。**时间轴单边**是这个偏置最常见的表现形式——因为"往后补"永远比"往回补"省事。
- **连带影响**：基于这个池子算出的任何比例都偏乐观。例如"120/201 有摘要（60%）"，因为池子里 90% 是新文章，而老文献摘要缺失更严重——**60% 只能当上限报，不能当估计报**。
- **为什么它比"漏检"更危险**：漏检是**可见的**（你知道自己少了几篇）；种子偏差是**不可见的**（你以为池子已经全了，只是在里面找得不好）。
- **对策**：
  1. 补池时必须**双向**：正向往后（谁引用了种子）+ 反向往回（种子引用了谁）
  2. 报告候选池时**连年分布一起报**，让偏置可见
  3. 任何"从别人给的清单出发"的情况，都要先问一句：这份清单是按什么筛出来的？

## 3. 判定层 —— 怎么保证"说得清"

### C1 输出固定九键，不给相关性结论 ✅
`doi / sections / coupling_type / material_scope / evidence_hints / criterion_refs / precedent_refs / caveats / needs_human`

- **理由**：签字的是人。工具只负责把证据摆到桌面上。

### C2 每条提示可追溯到规则与句子 ✅
- 每条 `Hint` 带 `rule / severity / field / text`；人能拿着它回到原文那一句核对。

### C3 `needs_human` 恒为 true ✅ / ⚠️
- **选择**：所有判定都留人工复核标记。
- **缺口**：⚠️ **它是个提示，不是回路**。人看完的判断没有地方可去——环目前靠人手合。

### C4 陷阱预警与召回提示分开 ✅
- 召回侧：多条检索轴、修正查询。
- 判定侧：R1/R2（可能是两组实验）、R5/R6（牺牲剂体系、头条数值来自牺牲剂组）、R7（单位混比）、R15（明说分步 → 串联伪装成耦合）。
- **R15 的来源**：用户原话"第一步制过氧化氢，第二步用制出来的过氧化氢去制别的材料，最终产品不含过氧化氢"。一句话 → 一条判据，中间没有训练过程。

## 4. 演进层 —— 环怎么转

### D1 漏检 → 改检索轴 ✅（人工）
- 通道有：`extraQueries` + `why`。但填的人是人。

### D2 误判 → 改判据 ✅（人工）
- 通道有：改 `rules.py`。R15 就是这么来的。

### D3 标注动作被系统承接 ✅（最小版）
- 已建：`scripts/review.py` — 分类型取样 → 逐篇 2/0/1 → 落 `data/labels.csv` → 立刻对账。
- 还缺：从标注**自动起草判据**。现在是人工看队列改 `rules.py`（下面第 8 节就是一次完整的人工回合）。
- 边界：**标注应该长出判据，不是长出权重**。权重打不开，判据能读、能改、能带走。

### D4 变更史 / 判例 ⚠️
- 现在只有 `git log`（给写代码的人看的）。
- 缺：原来怎么写的、为什么改、改之前判过多少篇。
- 判例的价值不在条文，在条文背后的那次判错。

### D5 影响面重判 ⚠️
- 加一条判据后要能回答"会改变之前判过的多少篇"。3 篇顺手看，300 篇要认真想。
- 不需要金集：把已有候选池重跑一遍做差分即可。

### D6 矛盾采样 ✅
- 已建：`scripts/contradictions.py` 四类分歧 + `scripts/review.py` 按判据签名分桶取样（12 篇覆盖 12 种类型，不是 12 篇近亲）。
- 不给"最像的 50 篇"，给**规则与人不一致的那批**：
  - 规则说像、人说不像 → 判据太宽
  - 规则说不像、人说是 → 判据太窄
  - 规则说像、人说不确定 → 这条线还没画
- 不需要训练：拿现有 14 条判据跑一遍就出队列。

### D7 新边界探测 ⚠️
- 天然信号：**一条规则都没命中的那批论文**——系统看不懂的，就是边界该扩的地方。
- 再加人工发现的零散漏检。

## 5. 边界 —— 主动声明不做

| 不做 | 理由 |
|---|---|
| ⊘ 取全文、绕反爬 | 要登录、没公开接口的一律不碰。不是做不到，是不该做。 |
| ⊘ 多模态看机理图 | "模型觉得是耦合"不可复核。评委问一句"凭什么"，答不上来。 |
| ⊘ 报覆盖率 | 分母不存在。只报下界：手上这几篇已知文献，都找到了没有。 |
| ⊘ 承诺"不漏" | 只承诺"漏了能查到、能说清为什么"。 |

## 6. 由这棵树直接推出的三件事

1. **材料的核心主张换顺序**：从"我们能算覆盖率"改成"**我们让'漏了什么'第一次变成可累积的东西**"。
2. **两套产品不是两条路**：专家版 = 人合环（已能用）；学生版 = 系统帮合环（D3 是关键）。
3. **三天内只做可测的**：D6（矛盾采样）不需要训练、不需要金集、拿现有判据就能出队列——是性价比最高的一块。

## 7. 别人在哪

| 别人 | 他们缺的那条 |
|---|---|
| ASReview / Rayyan / Covidence / PRISMA-LLM / MechaScreener | 输入是**已建好的池子**；池子缺了哪几篇，无人负责、无指标可发现 |
| ResearchRabbit / Litmaps | 能造池子，但按相似度造，不按标准造；给不出"它为什么进来"的账 |

> 一句话：**别人在判断"相不相关"，我们在判断"属于哪一类"——而这两类在检索结果里长得一模一样。**

## 8. 环第一次真正转动（2026-11-15 晚）

这是这段设计第一次被真实数据推着改动。全过程 ≈ 40 分钟，没有训练、没有金集。

**原料**：按 DOI 从 OpenAlex 拉回摘要。
- 金集 9 篇 → OpenAlex 有记录 8 篇，其中 **6 篇有摘要**（`10.1016/j.mser.2025.101117` 查不到）。
- 候选池 201 篇 → 命中 200 篇，其中 **120 篇有摘要、81 篇没有**。

**第一次跑队列，结果很难看**：6 篇有摘要的金集阳性，**全部**被判据判成"有问题"（误报率 100%）。

**归因**：
- R2 只认 `simultaneous` 一个词。实测这 6 篇里用的是 `coupled`（3 次）、`concurrent`（2 次）、`simultaneous`（仅 1 次）。
- R1 认为"标题含 and"可疑，但 `... Production and Organic Synthesis` 本身就是耦合。
- R8 只要"存在空格化学式"就报，而 OpenAlex 把下标一律渲染成空格 → **120 篇里 87 篇命中，72.5%**，测的是数据源不是论文。

**修正**（三处，都只有几行）：
| 改什么 | 怎么改 | 效果 |
|---|---|---|
| R1 | `medium` → `low`，文案改为"请确认" | 不再算作"判据说有问题" |
| R2 | 从 1 个词扩到一组（coupled / coupled with / concurrent / tandem / one-pot / co-production…） | 金集误报 5/6 → 1/6 |
| R8 | 从"有空格式子"改为"空格式子**+ 紧邻数值声明**" | 触发率 72.5% → 30.8% |

**修正后**：队列从 6 条误报降到 **2 条真问题**，而且两条都是该问的：
1. Vinylene-COF：R5/R6 说头条数值来自牺牲剂组 —— 人工记录确认"headline 17768 belongs to the sacrificial run"，这属于**该报的陷阱**，不是误判。
2. 甲烷→乙醇：R2 说没有同时发生类表述 —— 摘要里确实一个字没提 H₂O₂，它靠的是 `no-product-word` 那条修正查询救回来的。**这正是"措辞完全不同"最硬的例子。**

**副作用（值得记）**：R8 收窄后，原来充当演示样例的手写 fixture 不再产生 high 提示。于是把 `docs/sample-decision.json` 换成**真实论文** `10.1021/jacs.6c00731` —— 它同时命中 R5/R6，与人工记录一致。样例从此是真输出，不是手写的。

**测试**：84 项 → **94 项**，全绿。

**这一圈证明了什么**：判据不是写出来的，是被数据打出来的。而"打"这个动作，现在有脚本了。
