# 一位使用者的测评（2026-11-18）与处置

> 原文要点：三条「白跑一趟」，两条功能缺口，一条小问题。
> 原话：「它们都会让人白跑一趟，而且**错在工具本身，不在用户**。」

## 三条「白跑一趟」

### 1. 包里没有时间维度 ✅ 已修

> 检索语句里放不进日期，「近三年」只能检索完再筛。而文献综述里「新」几乎排第一。

**修法**：`pack.json` 新增 `dateWindow: { since, until }`，直接进 OpenAlex filter
（`from_publication_date` / `to_publication_date`）。
校验器：没有 `dateWindow` 就警告，并明说「时间只能事后筛」——不让工具假装管了这件事。

### 2. 单复数 ✅ 校验器已拦，包内容待改

> `"covalent organic framework"` 匹配不到 frameworks。我第一批 18 条正例只找到 9 条，补上复数后变成 16 条。

**这条是我们自己的包也中招的**：`cof-h2o2` 有 7 处单数，`cv-finance-esg` 有 18 处。
其中 `covalent organic framework` 正是被点名的那个。

**已做**：`validate-pack` 逐词检查带引号的短语，缺复数就警告；同时给 `pluralExempt`
豁免机制——化学名（`hydrogen peroxide`）没有复数，这种例外必须写进包里留痕，
不能靠口头说「这个不用管」。

**没做，而且刻意不做**：暂时不改包里的查询词。
改了查询，2/7 → 5/7 → 7/7 这组数字全部失效，而 OpenAlex 额度要到 UTC 零点才恢复。
**宁可比预期晚一天，也不能让文档里的数字和代码对不上。**
恢复后一次性做：补复数 → 重测 → 同步更新文档、材料、deck。

> 另：单复数检查第一版报了 39 条警告，其中一堆 `satellite imageries`、`chart answerings`
> 这种根本不存在复数的词。加名词化后缀过滤（-ing/-tion/-ment/-ity…）后降到 18 条，每条都真的可加。
> **噪音会让真正的坑被淹掉**，这条本身也是教训。

### 3. 通配符 ✅ 已修

> `fluorinat*` 直接返回 400。报错信息清楚，但必须先跑一次才会发现。

**修法**：`validate-pack` 离线拦截——维度词、槽位词、`extraQueries` 里出现 `*` 或 `?` 直接报错，
并说明原因（`title_and_abstract.search` 按词干检索，不接受通配符）。

## 两条功能缺口

### 4. 候选池拿不全 ✅ 已修

> `search_candidates` 只返回 50 条样本，可我池子里有一千多条却拿不到。

`search_candidates` 新增 `dumpPath`：整池写成 CSV，只回路径和条数，不塞进消息体。
另外加了 `sampleSize`（默认 50）和 `provenance` 字段——顺手把「这份清单怎么来的」塞进返回值。

### 5. 无金集也能做召回自查 ✅ 已修

> 拿二十几篇已知的好文章当种子，看每条查询能召回几篇。不需要 gold 就能跑。

```bash
node bench/run.mjs --probe 10.1/a,10.1/b,... --quiet
```

逐条查询报「召回了几个种子」，并给出每阶段并集与总并集，最后列出「一条都没召回」的那几篇。
实测（7 篇金集阳性当种子）：A 阶段并集 2/7、B 5/7、C 7/7，其中 C·8 只找回 1 篇——
**一条查询救回一篇，这种账只有种子召回能记下来。**

### 6. `coverage_report` 在 MCP 里超时 ✅ 已缓解

> 命令行跑完只用了 52 秒。

查了 `server.ts`：**我们这边没有写死任何超时**，掐断的是 MCP 客户端。
所以不硬扛，改成「让响应变小」——`coverage_report` 新增 `dumpPath`，
完整报告落盘，只回摘要。要跑全量 stage C 建议走命令行，或分维度跑。

## 最重的一句

> **那四句开场白比三个工具加起来有用。** 尤其第三句——「这份清单是从哪来的、按什么筛的」。
> 这轮我就是在那句上栽的，而且是我先栽的，工具后来才把这句话写进去。

这是产品信号，不是客套：

- 用户最先需要的是**知道这份清单的来历和筛选口径**，不是更多功能；
- 而且他自己也栽过——**说明这一步连熟手都会漏**；
- 「工具后来才把这句话写进去」——文档不是功能的附属品，它承担了主要价值。

**对下一步的影响**：与其继续加工具，不如把 `intake` 的四问、以及每份产出的「来历与口径」
做成必须显式回答的字段——现在它是文档里的一段话，还不是产物里的一个结构。

## 关于「错在工具本身」这句判断

七条里有六条是工具的责任。这和我们自己的发现是一致的：
判据账、漏检账、`--works` 离线题录，都是同一个问题的不同侧面——
**工具默认自己的输入是干净的、完整的、口径明确的，而事实从来不是。**
