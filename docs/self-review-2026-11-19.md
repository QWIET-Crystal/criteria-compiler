## 会改变结论的三个

### 1. 标题和摘要用空格拼接，造出假共现【已证实】

调用方 6 处写的是 `` `${work.title} ${work.abstract}` ``，而生成共现对的
`findCooccurrences` 用的是 `` `${title}. ${abstract}` ``。

标题**没有结尾句号**时（OpenAlex 常见），标题会和摘要第一句黏成一句。
于是「标题里的词」和「摘要第一句里的词」被判成「同一句出现」。

实测：

```
同一篇论文
  空格拼接 → 判据命中「2 个说法落在第 1 句里」
  句号拼接 → 判据不命中「分别出现但不在同一句」
```

**换个拼法，结论就反了。**

修法：`criteria.mjs` 导出唯一的 `workText(work)`，所有调用方都走它，不许自己拼。

### 2. 生成器用 `includes`，求值器用词边界【已证实】

`findCooccurrences` 里是 `sentence.includes(term)`，没有词边界；而 `spansOf` 有。
两套规则的结果是：**生成出一条共现判据，求值器永远不命中它。**

实测：生成器说「`synthesis + aerobic` 是共现对」，求值器说「`synthesis` 整篇都没有」
——因为它只在 `photosynthesis` 里出现过。

生成出来就死的判据，比没有更糟：它占着位置，还让人以为覆盖了。

修法：生成器改用与求值器同一套匹配；测试里加了「生成出来的每一条，求值器都必须认得出」的契约。

### 3. 判定规则写了 5 份，而且已经不一致

| 位置 | 规则 |
|---|---|
| `refine.mjs` decideWith | 二值（共现不中 = 不算） |
| `refine.mjs` 重拉打分 | 二值 |
| `refine.mjs` 旧条目带过来 | 二值 |
| `try.mjs` | **三值**（算 / 疑似 / 不算） |
| `ledger.mjs` | **三值** |

同一篇论文，`try` 说「疑似」，`refine` 说「不算」。

而 `refine.mjs` 那行注释还写着「与 bench/try.mjs 保持一致」——**注释是假的**。

修法：规则收进 `criteria.mjs` 的 `decide()` 一处，五处全部改调它。
测试覆盖三档 + 排除信号优先。

## 会让工具说谎的四个

### 4. 队列只认「算」，把「疑似」全滤掉

重拉队列的打分只给「共现命中」和「排除信号」分，**「疑似」得 0 分被丢弃**。

而那些恰恰是最该让人标的：工具拿不准，人一眼能定。
旧逻辑让队列显得很干净，代价是绕过全部边界样本。

修法：打分改成三档，疑似得 3 分并明确标注「最值得你亲眼看的一批」。

### 5. 队列按引用数排序，被 1961 年的老文章占满

排序尾项是 `cited`，于是「分子内电荷转移」这类 1960–2000 年的高被引文章排在最前。

文献综述里「新」比「被引多」要紧——**这一点使用者测评的第一条就点出来了**。

修法：尾项改成年份新的优先，引用数只做最后兜底。

### 6. 拉池子失败会显示成「没有新论文」

`fetchPool` 里 `api()` 失败返回 `null`，被当成「这一页没有结果」，最后返回空数组。
使用者看到的是「下一轮队列 0 篇」——像是一个结论。

修法：统计失败页数；一页都取不到时**直接退出并说明**（额度用完 / 网络不通），
不写出任何基于空池子的产物。顺带加了诊断行：
`拉到 100 篇｜已看过跳过 12 篇｜命中判据 88 篇`——一眼看出「0」是怎么来的。

### 7. 没有类型过滤，peer-review 和数据集混进池子

真实队列里出现了 DOI 长这样的记录：`10.1039/d5sc01916h/v1/review2` ——**审稿意见**。

OpenAlex 把 peer-review、dataset、paratext 也当 work 返回，我们没筛。
它们不是论文，却占名额、还会被当成候选让人去标。

修法：`select` 加 `type`，收池时只要 `article / review / preprint / letter`。

## 三个运行时/边界问题

### 8. `refine.mjs` 里 `const record` 遮住了导入的 `record()`【会崩】

加 provenance 时导入 `record()`，但同文件里有一个 `const record = {...}`（历史记录对象）。
调用时直接 `record is not a function`。

修法：导入改名 `record as recordProvenance`。

### 9. `parseCsv` 不处理 BOM

Excel / PowerShell 导出的 CSV 带 BOM，表头会变成 `\uFEFFdoi`，
于是每一行的 `doi` 都取不到——**而且不报错**。

修法：解析前剥 BOM；测试覆盖。

### 10. `termsOf` 在标题/摘要交界处造出假双词

`` `${title} ${abstract}` `` 拼完再切词，会在交界处生成一个原文并不存在的双词
（标题末词 + 摘要首词），而双词是按相邻对生成的。

修法：标题、摘要分别切词再拼接。

## 两个低危但该修的

### 11. `--probe` 把每条查询跑了两遍

算「每阶段并集」已经跑过一遍，算「总并集」又从头跑一遍。查询数是双倍。
修法：把各阶段并集合并即可。

### 12. 判据账的统计口径混了

「弱信号」同时被算进「没认出」，还和「完全没命中」抢原因归属。
一条论文会同时出现在「疑似 3 篇」和「原因未定」里。

修法：只有 `missed` 才要求定原因，弱信号单独一行报。

### 13. `window` 写在 jsdoc 里但从没实现

`criteria: [{ ..., window? }]` 是文档漂移，照着写会以为有窗口参数。
修法：删掉，换成实际支持的 `scope`。
