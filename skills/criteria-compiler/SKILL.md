# Criteria Compiler

结论由人下。本 skill 只负责把“该看哪、哪里可能有坑”指出来。

## 何时用

- 用户按关键词找不到足够文献，说“只找到几篇”
- 用户有一批人工判定过的文献，想把标准交给别人复现
- 需要回答“某个检索口径覆盖了多少金集”

## 起步：先问，再搜

**第一次用一个新领域，不要直接开跑。** 先问四句，再动手：

1. **你要搜的是哪一类东西？** 一句话，外加三个你认得的例子（带 DOI 最好）。
   → 用来定槽位候选。
2. **什么算“算”？给我三个算的、三个不算的。**
   → 判据从这三个正反例里长出来。**跳过这一步，后面全是猜。**
3. **这份清单、这些关键词，是从哪来的？** 别人给的，还是你自己搜的？
   → 若是别人给的，追问一句“按什么筛的”。**从已筛清单出发会继承它的筛选偏置，而且看不出来。**
4. **时间范围？** 只往后补，还是要往回补？
   → 只往后补是最常见的偏置形态：地基（2021–2023）整段缺失，而清单看上去是“全的”。

答完写进 `packs/<新包>/intake.md`，再开始第 1 步。

### 一条命令，把四个答案变成可以改的东西

```bash
node bench/start.mjs --id <新包名> \
  --want "一句话说你要搜什么" \
  --pos <DOI>,<DOI>[,<DOI>] \
  --neg <DOI>[,<DOI>]
```

它做三件事，**都不替你做判断**：

1. 从你的正反例里长出**区分词**，再用同领域背景池把「这个领域的通用词」筛掉——只给正例的话，「photocatalysts」这种词当然满足「正例里有、反例里没有」，那不是判据，那是领域常识。
2. 输出一份 `draft.json`：几个候选检查 + 每个检查是**从哪几篇长出来的**。它一定不完美，它就是要给你改的。
3. 按草案挑出「最该由你来标」的那批，写进 `review-queue.csv`（最后一列填 2/0/1）。挑的规则是**贴着交集边缘**的论文——离题目太远的，标了也不长知识。

### 标完回来，让它改

把 `review-queue.csv` 最后一列填好 2 / 0 / 1，然后：

```bash
node bench/refine.mjs --pack <新包名>
```

它做三件事：

1. **对账**：你判「算」但它说「不算」→ 判据太窄；反过来 → 太宽。
2. **改判据**：太窄的，从那些论文里长出新的区分词；太宽的，长出排除信号。
   —— 有一道硬闸门：已经进了「算」词表的词，绝不会再被提议成排除信号。
   这两批论文共享同一个领域的词汇，没有这道闸门，第一次闭环就会把判据自己打死。
3. **压短下一轮**：标过的论文不再问你。这就是「越用越懂」的全部实现——
   不是训练模型，是从你标错的地方长出词。

如果找不到干净的排除词，它会明说，并给出正确的方向：
**该问「这几篇缺了什么」，而不是「它们多了什么」。**

### 改判据，立刻看后果

```bash
node bench/try.mjs --pack <包名>
```

只读，不写。它把草案里的每条 `criteria` 跑在你标过的论文上，**且每条判断都附原文片段**：

```
[Aerobic Oxidation] 与 [Asymmetric]     ← 一眼看出这是废话对
```

改判据的方式就是直接编辑 `draft.json` 里的 `criteria`，再跑一遍。人给概念，机器做记账。

规则（`try.mjs` 与 `refine.mjs` 一致）：踩到排除信号 → 不算；否则有共现判据就以共现为准，没有才退回 `any`。

**注意**：改完判据，旧队列就过期了——队列是按上一版判据挑的，得重新拉一批。

### 不要替用户决定槽位

槽位怎么切是**领域判断**，不是参数值。正确做法是给 2–3 种切法，把每种的实际后果量出来，再让用户选：

```bash
node bench/axis-yield.mjs --pack <候选包>
```

实测过的反例：把“视觉 × ESG”硬套两个槽，各自 43 万 / 75 万篇，AND 之后只剩 **350 篇（0.1%）**——因为那个领域的论文写任务名（表格抽取、图表理解），不写学科名（计算机视觉）。

**这时候不是改词表，是回去问用户“你要的到底是哪一种视觉工作”。**

## 三步

1. `search_candidates` —— **按检索轴并行召回**。不要单轴检索：召回上限由维度决定，排序改不了。
2. `check_paper` —— 单篇体检：归一化、规则触发、材料归属。
3. `coverage_report` —— 输出口径 × 覆盖率表。

三个工具都接受可选 `pack` 参数（包目录），不传就用默认包。**换领域靠换 pack，不是换参数值。**

但注意：**换 pack 不等于只换词。** 槽位怎么切、检查项写哪几条，都要重新设计，而且必须由人拍板——这两件事靠换词表换不过来（见上文「不要替用户决定槽位」）。

## 铁律

- 不给“相关 / 不相关”的终判，只给证据提示与陷阱预警
- 每条判定必须能引用判据编号或判例编号
- 不抓付费墙、不绕过人机验证、不下载全文
- 化学式一律用 `normalizeForMatch` 比对，别写死 `H2O2`
- **pack 没有金集时不许报覆盖率**：只能给候选池大小与各轴产出，报百分比就是编

## 实测陷阱（来自真实数据，不是想象）

- 接口返回的化学式带空格：`H 2 O 2`、`Bi 2 O 2 S`、`CuInS 2`
- 摘要头条最高产率常来自“牺牲剂体系”，不是耦合体系（实测差三个数量级）
- 标题里的 `and` 不可靠；`series / tandem / stepwise` 多为两步串接
- `anie.` 与 `ange.` 是同一篇的两个 DOI
- 部分记录没有摘要，检索接口不返回，只能按 DOI 直查

## 判定要看的三处

1. **图**：是否存在一张图同时给出两种产物随时间变化（最可靠，30 秒）
2. **正文**：`simultaneous` 出现次数、两套实验的溶剂是否不同
3. **收率**：有机产物有没有给出收率/选择性；没有数字只能定性引用
